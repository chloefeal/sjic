# 姿态按人计时

考场高位摄像头里，考生坐在各自的考试机前，考试过程中不换座。近处的人很大，后排的人很小。边缘盒子的 CPU 和 GPU 已经在跑姿态推理，认人不再加载跟踪、重识别或人脸模型。

同一个人是「还坐在这张桌子上的那个人」，只用来把几秒内的姿态接到一起，不是考生身份。

## 以前的问题

点状违规（张望、侧看、低头、捂嘴、手指屏幕）和眼镜、手表的触碰，原来一个场景共用一条计时和冷却。

- 本帧只要有一个人命中，这条场景的时间就继续走。A 低头 2 秒后抬头，B 刚开始低头，两个人各自都没满 3 秒，场景仍可能报警。
- 报完一个人之后，整条场景进入冷却，这段时间里其他人再违规也不再报。

人数类规则本来就是数这一片区域里有多少人，仍然共用一条计时。

## 怎么判断是同一个人

每一帧只做一次关联，点状场景和眼镜、手表都用这些轨迹。实现在 [edge-agent/algorithms/pose_behavior.py](../edge-agent/algorithms/pose_behavior.py) 的 `PersonTracker`。姿态任务和混合任务（[exam_pipeline.py](../edge-agent/algorithms/exam_pipeline.py)）共用它。

锚点按这个顺序取，尺度跟着锚点走：

1. 双肩中点，尺度是两肩的距离。这个角度下髋部经常被桌子挡住，头和检测框会跟着趴桌、侧看移动，肩膀还在椅子上。
2. 没有可靠的双肩时，用双髋中点，尺度用框宽。
3. 关键点都不可用时（后排小人常见），用框中心，尺度用框宽。

当前检测和仍活着的轨迹按距离从小到大一对一分配。两边都还没被占，并且距离小于门槛，才算同一个人。有肩宽时门槛是 `0.75 × 肩宽`，否则是 `0.5 × 框宽`。近处人和远处人差好几倍，所以用身体尺寸，不用固定像素，也不用框高。高位看下去框高往往大于到邻座的距离，用框高会把旁边的人盖进去。检测框的重叠面积也不用：人一趴向屏幕，框就变了，3 秒计时容易被拆断。

四十来人就是一两万次距离比较，相对一次姿态推理可以忽略。

## 轨迹 id 上记什么

每条轨迹有一个只在当前任务里使用的 id。各场景在这条轨迹上单独累计：

- 点状违规的持续时间和上次报警时间。只有这个人自己的姿态连续达到设定秒数，才报这个人。A 的时间不会加到 B 上，A 报警后的冷却也挡不住 B。
- 智能眼镜、智能手表的触碰次数。

这个人仍被检出、但姿态已经不满足，只清这个人的这条计时。连续两帧推理都没再检出，轨迹还留着，第三帧仍然没有才丢掉，再出现算一条新的。推理大约 1 次/秒时，这两帧大约是 2 秒。漏检的这段时间仍算在持续时长里，所以关键点闪一两帧不会把快满 3 秒的计时清掉。

上一帧还在的人，不管两次推理隔了多久，都按位置接上。盒子慢到大约 1 秒才出一帧，人还坐着，计时也不会断。

## 不按人跟踪的规则

缺席、滞留、聚集、考试员不巡场只数区域内的人，不走这套轨迹。

## 不做的事

不引入 ByteTrack、卡尔曼滤波、外观直方图、ReID 或人脸。考场座位不动，邻座距离通常大于一肩宽，这些模型要么再占 GPU，要么还要裁图占 CPU。
